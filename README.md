# SPoS-MSC Reproducibility Package

**Executable Modelling of a Scalable Mobile Smart-Contract Lifecycle with Incentive-Aware Proof-of-Stake Governance**

This repository supports the formal model, scenario data, prototype implementation, statistical analysis, and figures associated with the SPoS-MSC study.

SPoS-MSC integrates:

- mobile request preparation and edge/access support;
- shard routing and load monitoring;
- owner-aware, mobile-aware, and risk-aware validator scoring;
- VRF-style committee formation and recovery;
- committee-controlled finality and commitment evidence;
- mobile receipt generation;
- validator rewards, slashing, and decentralisation monitoring.

## Important provenance statement

The repository intentionally separates three evidence types:

1. **CPN model artefacts**: CPN Tools models and model documentation.
2. **CPN-proxy datasets**: the primary Q1–Q7 output matrices reproduce the manuscript headline totals and were generated by a model-faithful Python execution of the integrated CPN semantics. Their embedded README explicitly states that they are not native CPN Tools monitor exports. Separate six-policy development workbooks are stored under `data/raw/internal_baseline_proxy/`.
3. **Prototype benchmark data**: run-level and aggregate outputs produced by the implemented SPoS-MSC prototype.

Before a journal-linked archival release, add the exact integrated CPN model used for the submitted manuscript and the native CPN Tools monitor exports, if the manuscript claims native CPN execution. See [`docs/RELEASE_BLOCKERS.md`](docs/RELEASE_BLOCKERS.md) and the publication workflow in [`docs/GITHUB_ZENODO_RELEASE.md`](docs/GITHUB_ZENODO_RELEASE.md).

## Headline results represented in the current package

| Evidence layer | Transactions | Finality certificates | Receipts | Finality success | Receipt success |
|---|---:|---:|---:|---:|---:|
| CPN/proxy evaluation | 192,404 | 173,089 | 170,369 | 89.96% | 88.55% |
| Prototype benchmark | 215,274 | 208,820 | 201,877 | 97.00% | 93.78% |

The prototype produced approximately **28,194 receipts/s** in a controlled single-host lifecycle benchmark. This is not public-network blockchain throughput.

## Quick start: prototype

Python 3.11 or later is recommended.

```bash
python -m venv .venv
source .venv/bin/activate        # Windows: .venv\Scripts\activate
python -m pip install --upgrade pip
pip install -r requirements-dev.txt
pytest -q
python scripts/run_scenarios.py --runs 100 --seed 626 --output outputs
```

Run the API service:

```bash
uvicorn spos_msc.main:app --host 0.0.0.0 --port 8000
```

Or use Docker:

```bash
cp .env.example .env
docker compose up --build
```

## Reproduce summaries and figures

```bash
python analysis/summarise_cpn_proxy.py
python analysis/summarise_prototype.py
python analysis/generate_figures.py
python scripts/validate_repository.py
```

Generated files are written to `outputs/reproduced/` and are not committed by default.

## CPN Tools

The component models were created with **CPN Tools 4.0.1**. Instructions and expected artefacts are in [`docs/CPN_EXECUTION.md`](docs/CPN_EXECUTION.md).

The exact integrated benchmark model must be copied to:

```text
model/integrated/SPoS_MSC_Complete_Benchmark_Hierarchical_Executable_v2.cpn
```

Use the import helper:

```bash
python scripts/import_integrated_cpn.py /path/to/SPoS_MSC_Complete_Benchmark_Hierarchical_Executable_v2.cpn
```
